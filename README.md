# Рапорт

**Рапорт** — линейка легких фронтенд-дашбордов для анализа Excel и CSV-отчетов.

Слоган: **Excel докладывает главное**.

Файлы обрабатываются локально в браузере и не передаются на сервер.

## Идея продукта

На промышленных предприятиях значительная часть управленческой информации живет в Excel, CSV-выгрузках, локальных отчетах и разрозненных таблицах.

«Рапорт» превращает такие выгрузки в понятные управленческие дашборды:

- показывает ключевые показатели;
- подсвечивает отклонения;
- находит зоны внимания;
- помогает быстро понять, где требуется действие.

## Дашборды

- `#/` — единая точка загрузки отчетов.
- `#/ssz` — качество оформления смено-суточных заданий.
- `#/tessa` — исполнительская дисциплина Tessa.
- `#/print` — контроль печати.
- `#/support` — SLA закрытых заявок техподдержки.

## Текущий стек

- React;
- TypeScript;
- Vite;
- Tailwind CSS;
- shadcn/ui primitives;
- lucide-react;
- IndexedDB для локальной истории KPI;
- xlsx для чтения Excel-файлов.

## Архитектура

Код актуальных дашбордов находится в `src/`.

```txt
src/
  features/
    ssz/
    tessa/
    print/
    support/
    file-loader/
    report-detector/
  pages/
    landing/
  shared/
    lib/
    styles/
    ui/
```

Основные правила:

- главная страница `#/` — единая точка загрузки файлов;
- тип отчета определяется по содержимому файла, не по имени;
- дашборды не имеют собственных upload-форм;
- бизнес-логика отделяется от React-компонентов;
- повторяемые UI-паттерны переиспользуются из `src/shared/ui`;
- новые дашборды должны выглядеть как часть одной линейки.

## Локальная история и тренды

Рапорт хранит агрегированные KPI-снимки в IndexedDB.

Правила:

- сохраняются только числовые агрегаты;
- сырые строки отчетов не сохраняются;
- ФИО, пользователи, документы и темы не сохраняются;
- шаг тренда — месяц;
- месяц попадает в тренд только при покрытии не меньше 50%;
- snapshot с большим или равным покрытием перезаписывает старый;
- snapshot с меньшим покрытием не затирает старый;
- для Print месячные KPI считаются без печати в PDF.

Управление локальной историей доступно на главной странице.

## Демонстрационные данные

Безопасные синтетические файлы для демонстрации находятся в `demo-data/`.

Доступный набор:

- `demo-data/ssz/demo-ssz-synthetic-may-2026.xlsx` — синтетический отчет ССЗ для демонстрации дашборда `#/ssz`.

Этот файл можно загрузить через главную страницу `#/`, чтобы показать:

- распознавание отчета ССЗ;
- KPI;
- фильтры;
- срезы по цехам, мастерам, заказам и операциям;
- зоны внимания;
- месячный тренд.

Реальные файлы для локальной проверки должны оставаться в `load_file/`. Эта папка исключена из Git.

## Роли в дашбордах

Для перегруженных дашбордов используется режим:

- **Руководитель** — компактный обзор, KPI, главный вывод, ключевые зоны внимания;
- **Аналитик** — полный набор срезов, трендов, таблиц и детальных виджетов.

Режим сохраняется локально в браузере. Переключатель режимов размещается компактно в панели `FilterStatusBar`.

## Правила для новых дашбордов

Новый дашборд должен:

1. загружаться через главную страницу;
2. определяться по структуре и содержимому файла;
3. иметь отдельные модули парсинга, типов, расчетов и UI;
4. использовать `PageShell`, `DashboardHeader`, `MetricCard`, `SectionCard`, `FilterPanel`, `FilterStatusBar`;
5. использовать Tailwind CSS, shadcn/ui и lucide-react;
6. не сохранять сырые данные в IndexedDB;
7. при необходимости добавлять месячные KPI snapshots;
8. проходить `npm run check`.

Подробные правила:

- `AGENTS.md`;
- `docs/tech-stack-rules.md`;
- `docs/design-system-spec.md`;
- `docs/ssz-final-style-contract.md`.

## Публикация

Production-сборка не привязана к домену или папке. Ее можно разместить, например:

```txt
https://example.ru/
https://example.ru/any/folder/
```

На сервер нужно переносить содержимое `dist/`.

Приложение использует hash-routing, поэтому серверу не нужен отдельный fallback для маршрутов дашбордов.

Примеры адресов после публикации:

```txt
https://site/folder/#/print
https://site/folder/#/ssz
https://site/folder/#/support
```

## Безопасность данных

Не публикуются:

- реальные производственные данные;
- персональные данные;
- внутренние адреса, логины, пароли и токены;
- коммерчески чувствительная информация;
- материалы под NDA.

Все примеры данных должны быть обезличены или синтетически сгенерированы.

## Известный риск зависимостей

`npm audit --omit=dev` сообщает о high-severity advisories в пакете `xlsx`. Автоматического исправления npm не предлагает. Сейчас Excel-файлы обрабатываются локально в браузере, ограничение загрузки — до 20 Мб.

## Локальная LLM-классификация Print

В дашборде Print есть опциональный локальный слой классификации потенциально личной тематики печати. По умолчанию он выключен, поэтому базовая работа дашборда остается прежней и использует словарные правила.

Принцип работы:

- фронтенд не обращается к Ollama напрямую;
- фронтенд отправляет только безопасный минимальный payload в локальный Node proxy: название документа, страницы, цветность, duplex и формат бумаги;
- пользователь, компьютер, принтер, дата и сырые строки отчета в LLM не передаются;
- при ошибке LLM дашборд автоматически возвращается к словарному fallback;
- результат отображается как сигнал для проверки, а не как доказанный факт личной печати.

Локальный запуск:

```bash
npm run print-llm:server
```

Переменные окружения см. в `.env.example`.

Для оценки качества на размеченной выборке:

```bash
npm run print-llm:evaluate -- --input path/to/labeled.csv --proxy http://127.0.0.1:8787/api/print/classify-personal
```
