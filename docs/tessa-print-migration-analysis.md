# Tessa/Print migration analysis

## 1. Scope

Цель: зафиксировать бизнес-логику и UX `legacy/tessa` и `legacy/print` перед визуальной миграцией в стиль ССЗ.  
Ограничения: без изменений кода и без изменения файлов в `legacy/*`.

---

## 2. legacy/tessa

### 2.1 Как запускается проект

- Рабочая версия запускается как Vite + React:
  - entry: `legacy/tessa/index.html` -> `/src/main.tsx`
  - npm scripts: `dev`, `build`, `preview` в `legacy/tessa/package.json`.
- Маршрутизации (react-router) нет, экран один.
- В папке есть legacy-файлы `legacy/tessa/app.js` и `legacy/tessa/styles.css`, но они не подключены в текущем `index.html`.

### 2.2 Загрузка файла и источник данных

- Загрузка CSV в браузере:
  - пустой экран drag-and-drop (`EmptyState`);
  - замена файла через карточку в хедере (`LoadedFileCard`).
- Парсинг через `Papa.parse` (delimiter `;`) в `src/lib/normalization.ts`.
- Для текущего экрана используется только процесс `"Согласование"` (`parseCsvFile(file, "Согласование")`).

### 2.3 Где расчеты и бизнес-логика

Ключевая логика в:

- `legacy/tessa/src/App.tsx`
- `legacy/tessa/src/lib/normalization.ts`
- `legacy/tessa/src/lib/filters.ts`
- `legacy/tessa/src/lib/metrics.ts`
- `legacy/tessa/src/lib/exportCsv.ts`

Основные правила:

- статусы: `В срок`, `Завершено с просрочкой`, `Открыто с просрочкой`, `Открыто в работе`;
- просрочка считается по `rawOverdue` и/или по дедлайну относительно `analysisDate`;
- deduplication строк через composite key;
- в экран попадают только договорные типы: `Договор`, `Дополнительное соглашение`, `Спецификация`;
- агрегаты строятся на “facts” по открытым задачам.

### 2.4 KPI

Отображаемые KPI:

- `Просрочены` (count + rate от открытых),
- `Истекают сегодня`,
- `Исполнителей с просрочками`,
- контекстно: `Открыто в работе`.

Расчет KPI: `calculateAgreementKpis` в `App.tsx` (локальная аналитика по отфильтрованным фактам).

### 2.5 Графики и таблицы

- Полноценных chart-компонентов нет (несмотря на зависимость `recharts` в package.json).
- Основные визуализации:
  - мини-таблица “Исполнители с застрявшими договорами”;
  - реестр проблемных документов карточками (`ProblemCard`);
  - segmented фокус-режимы для набора данных.

### 2.6 Фильтры

Панель фильтров (`FilterPanel`) в левом sticky-сайдбаре.

Состав:

- `Договор` (contractNumber),
- `Ответственный` (responsible),
- `Вид` (subject),
- `Автор` (author),
- `Тип документа` (details),
- `Юр. лицо` (details).

Дополнительные особенности:

- default значения: пустые строки + `focusMode = "stuck"`;
- фильтры применяются автоматически;
- есть reset кнопка (`Сбросить`);
- есть статусная полоса/аналог: `ActiveFilters` (чипы активных фильтров + счетчик `filtered/total`);
- есть очистка отдельных фильтров через `x` на чипе.

Взаимосвязь фильтров:

- опции фильтров пересчитываются на базе текущего контекста;
- невалидные выбранные значения сбрасываются в `useEffect`.

### 2.7 Переключатели

Переключатели и режимы:

- `focusMode` (по умолчанию `stuck`): `Просрочены / Истекают сегодня / Все в работе`;
- отдельный segmented в реестре: `Все / Просрочены / Истекают`;
- в таблице исполнителей: `ТОП / Все`.

Влияние на данные:

- `focusMode` участвует в фильтрации “facts” и в построении опций фильтров;
- `ТОП / Все` влияет только на объем показа (slice), не меняет расчеты.

### 2.8 Состояния ошибок/пустых данных

- загрузка: `Идет обработка данных...`;
- ошибка чтения/валидации CSV: `raport-notice-danger`;
- предупреждения по качеству дат;
- пустое состояние до загрузки;
- частичный empty state в реестре (показано 0 и т.д.).

### 2.9 CSS и иконки

CSS:

- активный стиль: `legacy/tessa/src/styles.css` (по структуре и токенам очень близок к SSZ).

Иконки:

- PNG-иконки через `BRAND.icons`:
  - `icon-upload`, `icon-problem`, `icon-time`, `icon-filter`, `icon-ranking`, `icon-table`, `icon-download`.
- Лого: `raport-logo-mark.png`.

### 2.10 Что можно заменить на shadcn/ui без изменения поведения

- фильтры: `Select`, `Input`, `Button`, `Popover/Command` (при сохранении текущей логики опций);
- status bar: `Badge`;
- KPI: `Card`;
- segmented переключатели: `ToggleGroup`;
- таблица исполнителей: `Table`;
- notices: `Alert`;
- download/reset: `Button`.

### 2.11 Какие иконки заменить на lucide-react

- `icon-upload` -> `UploadCloud`
- `icon-problem` -> `AlertTriangle` (или `CircleX` для error)
- `icon-time` -> `Info`/`Clock3` (если нужен строгий семантический тайминг)
- `icon-filter` -> `Filter`
- `icon-ranking` -> `Gauge` (или `ClipboardCheck` для дисциплины)
- `icon-table` -> `FileSpreadsheet` / `ClipboardList`
- `icon-download` -> `Download`

### 2.12 Риски миграции (tessa)

- Логика `focusMode` встроена одновременно в фильтрацию и генерацию option lists; визуальный рефактор может случайно изменить доступные значения.
- Реестр карточек документов имеет сложное ранжирование (`rating`, `stuckCount`, `maxStuckDays`); нельзя менять sorting/группировку.
- Есть технический “шум”: в корне `legacy/tessa` лежат неиспользуемые `app.js/styles.css` (идентичны `legacy/print`), важно не перепутать источник правды.

## 3. legacy/print

### 3.1 Как запускается проект

- Статический HTML+JS:
  - `legacy/print/index.html`
  - `legacy/print/app.js`
  - `legacy/print/styles.css`
- npm-скриптов нет; маршрутов нет; один экран.

### 3.2 Загрузка файла и источник данных

- Загрузка CSV через `<input id="csvInput">`.
- Парсер ручной (`parseCsv`) в `app.js`, expected CSV с обязательными колонками `CSV_COLUMNS`.
- После загрузки:
  - валидация колонок;
  - нормализация (`normalizeRow`);
  - автозаполнение фильтров;
  - рендер KPI, баров и таблиц.

### 3.3 Где расчеты и бизнес-логика

Ключевые блоки `legacy/print/app.js`:

- классификация типов документов (`classifyDocType`);
- классификация формата бумаги (`classifyPaperFormat`);
- эвристика “избыточной печати” по regex-словнику (`EXCESS_KEYWORDS`);
- риск-скоринг заданий (`riskScore`, `riskReasons`);
- фильтрация (`applyFilters`);
- расчет KPI (`renderKpis`);
- рейтинги/топы (`renderTopUsers`, `renderRiskJobs`);
- оценка стоимости (`estimateRowCost` по настраиваемым тарифам).

### 3.4 KPI

Виджеты:

- всего страниц / заданий;
- доля односторонней печати;
- доля цветной печати;
- задания от 100 стр.;
- уникальные пользователи;
- оценка стоимости.

### 3.5 Графики и таблицы

- chart-library нет;
- “графики” реализованы как bar-list с шириной через inline style (`style="width:%"`):
  - тип документа,
  - формат бумаги,
  - категории избыточной печати.
- таблицы:
  - топ пользователей (sortable, top 10/20),
  - топ заданий с отклонениями (sortable, top 10/20).

### 3.6 Фильтры

Состав (левая панель):

- период `с/по`,
- пользователь (autocomplete + clear),
- компьютер (autocomplete + clear),
- документ (text),
- тип документа,
- цветность,
- двусторонняя печать,
- формат бумаги (checkbox group),
- причина отклонения,
- чекбокс “Исключить печать в PDF”,
- reset.

Поведение:

- фильтры применяются автоматически;
- при reset:
  - очищаются текстовые/select фильтры;
  - `excludePdfPrinter = true`;
  - paperBucket defaults: `до A4 включительно` + `Не определено`.
- есть блок состояния пустой выборки: `filterEmptyNotice`.

### 3.7 Переключатели

Есть переключатели/режимы, влияющие на поведение:

- лимиты таблиц: `10/20` (для users и risk);
- сортировка top users: `pages | cost | noDuplexPages | colorPages | bigJobs`;
- сортировка risk jobs: `riskScore | totalPages`.

Значения по умолчанию:

- `users = 10`, `risk = 10`,
- `userSort = pages`,
- `riskSort = riskScore`.

### 3.8 Состояния ошибок/пустых данных

- ошибка загрузки/валидации CSV (`loadError`, `statusPill = "Ошибка загрузки"`);
- empty state до загрузки;
- empty-row сообщения в таблицах;
- notice при пустом результате фильтров.

### 3.9 CSS и иконки

CSS:

- `legacy/print/styles.css` — тяжелый legacy-стиль (темный сайдбар, serif-типографика, фиксированный min-width).

Иконки:

- самописных SVG нет;
- в таблицах используются теги/цветовые бейджи, но явных lucide/PNG-иконок в UI почти нет;
- визуальные статусы построены на цветах и pills.

### 3.10 Что можно заменить на shadcn/ui без изменения поведения

- KPI/панели: `Card`;
- фильтры: `Input`, `Select`, `Button`, checkbox-группы на `Checkbox`;
- autocomplete: `Popover + Command`;
- toggle лимитов: `ToggleGroup`;
- сортировки: кнопки в `Table` headers;
- уведомления: `Alert`;
- badge причин риска: `Badge`.

### 3.11 Какие иконки заменить на lucide-react

Минимально нужный набор при унификации со стилем ССЗ:

- загрузка CSV -> `UploadCloud`;
- ошибки -> `AlertTriangle` / `CircleX`;
- фильтры -> `Filter`;
- печатный контекст -> `Printer`;
- файл отчета -> `FileSpreadsheet`;
- сброс фильтров -> `RefreshCcw`.

### 3.12 Риски миграции (print)

- Высокий риск регрессий в фильтрах: много связанных условий (`paperBuckets`, `riskReason`, `excludePdfPrinter`, периоды, autocomplete).
- Риск изменения сортировки и лимитов top-таблиц при замене на новые компоненты.
- Риск с локализацией regex-классификации “избыточной печати”: нельзя менять словарь и веса без отдельного согласования.
- Inline width в bar-элементах нужен для визуального масштаба; перенос в React/Tailwind должен сохранить формулу.
- Сильная зависимость от legacy CSS; требуется изоляция через `.print-dashboard` на этапе миграции.

## 4. Сравнение и выводы для миграции

### 4.1 Факт по источнику бизнес-логики

- `legacy/tessa`: источник правды — React-код в `src/*`.
- `legacy/print`: источник правды — `index.html + app.js + styles.css`.
- Технический артефакт: `legacy/tessa/app.js` и `legacy/tessa/styles.css` идентичны `legacy/print`, но не используются текущим `legacy/tessa/index.html`.

### 4.2 Что обязательно сохранить

- Tessa:
  - логику `focusMode` и пересчет доступных фильтров;
  - группировку/рейтинг проблемных документов;
  - default `focusMode = stuck`.
- Print:
  - весь набор фильтров и их defaults;
  - формулу риск-скоринга;
  - сортировки и лимиты в таблицах;
  - расчет стоимости по тарифам.

### 4.3 Рекомендации перед стилизацией под ССЗ

- Для `/tessa` брать за основу текущий `src/styles.css` + компоненты из `src/App.tsx` (а не legacy `app.js`).
- Для `/print` начать с CSS-изоляции (`.print-dashboard`) и поэтапной замены блоков на Tailwind/shadcn без изменения JS-логики.
- Во всех дашбордах унифицировать иконки на `lucide-react` по семантике из `docs/09_tech_stack_rules.md`.
