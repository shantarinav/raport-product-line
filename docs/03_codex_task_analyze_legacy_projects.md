# Codex Task 03: анализ legacy-проектов Tessa и Print перед применением стиля ССЗ

## Цель

Проанализировать `legacy/tessa` и `legacy/print`, чтобы безопасно применить к ним визуальный стиль ССЗ.

## Важно

Ничего не менять.

# Технологический стандарт интерфейса

При миграции интерфейс должен использовать:

- **Tailwind CSS** — для стилей, сетки, отступов, состояний, адаптивности и цветовых токенов.
- **shadcn/ui** — для базовых UI-компонентов.
- **lucide-react** — для всех иконок.

Запрещено использовать:

- собственные SVG-иконки, если есть подходящая иконка в `lucide-react`;
- сторонние UI-kit библиотеки, кроме `shadcn/ui`;
- CSS-in-JS;
- inline styles;
- новые отдельные CSS-файлы под конкретный дашборд без необходимости;
- hardcoded-цвета внутри компонентов, если можно использовать Tailwind token или CSS variable.

Допустимо использовать CSS-файлы только для:

- общих CSS variables;
- базовых theme tokens;
- временной изоляции legacy-стилей, например `.print-dashboard`;
- технических случаев, которые сложно или нецелесообразно выразить Tailwind-классами.

Все новые или обновленные UI-компоненты должны быть React-компонентами, стилизованными через Tailwind classes и, где уместно, построенными на shadcn/ui primitives.


## Что изучить

Для каждого проекта определить:

- как запускается проект;
- какие есть маршруты;
- где находится загрузка файла;
- где находятся расчеты;
- какие есть KPI;
- какие есть графики;
- какие есть таблицы;
- какие есть фильтры;
- какие есть переключатели;
- какие есть состояния ошибок;
- какие CSS-файлы используются;
- какие элементы можно визуально привести к стилю ССЗ;
- какие элементы можно заменить на shadcn/ui без изменения поведения;
- какие иконки нужно заменить на lucide-react;
- какие риски есть при миграции.

## Особое внимание

Фильтры:

- состав;
- расположение;
- значения по умолчанию;
- логика применения;
- кнопка сброса;
- взаимосвязь фильтров;
- статусная полоска или аналогичный блок состояния;
- какие shadcn/ui компоненты можно использовать без изменения логики.

Переключатели:

- где находятся;
- какие режимы включают;
- какое значение по умолчанию;
- как влияют на данные;
- можно ли визуально оформить через shadcn/ui `Switch`, `ToggleGroup` или `Tabs` без изменения поведения.

`/print`:

- расчеты;
- структура данных;
- фильтры;
- переключатели;
- расположение виджетов;
- старый CSS;
- риски визуальной миграции;
- какие legacy styles нужно изолировать через `.print-dashboard`.
