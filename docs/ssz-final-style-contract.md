# Финальный визуальный контракт ССЗ

Действующий визуальный эталон компонентов - текущая рабочая реализация `/ssz` в `src`.

Источник контракта:

- `src/pages/ssz/index.tsx`
- `src/features/ssz/components/SszDashboardPage.tsx`
- `src/shared/ui`
- `src/shared/styles/theme.css`
- `src/index.css`
- `tailwind.config.ts`

`components.json` и `src/App.css` в текущей структуре отсутствуют.

## 1. Shared/UI компоненты, используемые в ССЗ

ССЗ должен использовать уже созданные компоненты из `src/shared/ui`:

- `PageShell` - общий контейнер страницы с фоном, шириной и внешними отступами.
- `DashboardHeader` - единая шапка дашборда.
- `FileDropZone` - загрузка Excel-файла до появления данных.
- `ErrorState` - ошибка импорта.
- `SectionCard` - карточки аналитических секций.
- `MetricCard` - KPI-карточки верхнего уровня.
- `FilterPanel` - боковая панель фильтров.
- `FilterStatusBar` - строка активных фильтров.
- `DashboardSwitch` - переключатели режимов `ТОП/Все` и статусов.
- `DataTable` - табличный fallback и стандарт для таблиц.
- shadcn-подобные primitives: `Card`, `CardHeader`, `CardContent`, `CardTitle`, `CardDescription`, `Button`, `Badge`, `Input`, `Select`, `ToggleGroup`, `Table`.

Внутри `SszDashboardPage` также есть локальные паттерны, которые считаются частью текущего контракта ССЗ:

- `ProgressStrip` - прогресс-линия с цветом статуса и маркером цели.
- компактная строка списка: название слева, `% + статус` справа, прогресс, затем строка метрик.
- `RankBadge` - номер рейтинга для блоков лидеров и зоны внимания.
- `RowNameButton` - кликабельное название с `truncate`.

Эти паттерны нужно переиспользовать или выносить в общие компоненты, а не создавать визуально похожие дубликаты.

## 2. CSS variables и Tailwind-классы как стандарт

Базовые токены находятся в `src/shared/styles/theme.css` и обязательны для всех дашбордов:

```css
--raport-bg
--raport-surface
--raport-surface-soft
--raport-text
--raport-muted
--raport-border
--raport-primary
--raport-primary-strong
--raport-success
--raport-warning
--raport-danger
--raport-neutral
--raport-action-bg
--raport-action-bg-active
--raport-action-border
--raport-radius-card
--raport-radius-control
--raport-shadow-card
```

Стандартные Tailwind-паттерны:

- фон страницы: `bg-[var(--raport-bg)]`;
- поверхность карточек: `bg-[var(--raport-surface)]`;
- мягкая поверхность: `bg-[var(--raport-surface-soft)]`;
- текст: `text-[var(--raport-text)]`;
- вторичный текст: `text-[var(--raport-muted)]`;
- границы: `border-[var(--raport-border)]`;
- основной акцент: `text-[var(--raport-primary)]`, `border-[var(--raport-action-border)]`, `bg-[var(--raport-action-bg)]`;
- активное действие: `bg-[var(--raport-action-bg-active)]`;
- радиусы: `rounded-[var(--raport-radius-card)]`, `rounded-[var(--raport-radius-control)]`;
- тень карточек: `shadow-[var(--raport-shadow-card)]`;
- числовые значения: `tabular-nums`;
- обрезка длинных названий: `min-w-0`, `truncate`, `overflow-hidden`, `text-ellipsis`, `whitespace-nowrap`.

`tailwind.config.ts` не расширяет тему. Поэтому визуальный стандарт задается через CSS variables и utility-классы, а не через кастомные Tailwind theme tokens.

## 3. Шапка дашборда

Шапка ССЗ оформлена через `DashboardHeader` и является единственным верхним блоком страницы.

Структура:

- слева бренд-блок;
- справа кнопка `Главная` и информация о загруженном файле;
- ниже в левой части описание дашборда.

Бренд-блок:

- логознак: `FileSpreadsheet` из `lucide-react`;
- контейнер логознака: `40x40`, `rounded-xl`, темный фон `bg-slate-900`, белая иконка;
- размер иконки: `h-6 w-6`;
- `strokeWidth={2.3}`;
- название: `Рапорт`;
- слоган рядом с названием: `Excel докладывает главное`;
- описание: `Качество оформления ССЗ: анализ доли работ по технологии...`.

Информация о файле:

- компактный блок на мягкой поверхности;
- `rounded-[var(--raport-radius-control)]`;
- `border-[var(--raport-border)]`;
- имя файла обрезается через `truncate`;
- период и время загрузки идут строками ниже.

## 4. KPI-карточки

KPI оформляются через `MetricCard`.

Стандарт:

- сетка: `grid gap-4 md:grid-cols-2 xl:grid-cols-3`;
- карточка: `Card` с верхней цветной линией `border-t-4`;
- tone задает цвет верхней линии:
  - `neutral` -> `--raport-neutral`;
  - `success` -> `--raport-success`;
  - `warning` -> `--raport-warning`;
  - `danger` -> `--raport-danger`;
- заголовок KPI: `text-sm`, `--raport-muted`;
- значение: `text-3xl font-extrabold leading-none`;
- примечание: `text-xs font-semibold`, `--raport-muted`;
- иконка: `h-4 w-4`, `--raport-primary`, `strokeWidth={2}`.

Tessa и Print должны использовать `MetricCard` для верхнеуровневых числовых показателей.

## 5. Карточки секций

Секции оформляются через `SectionCard`.

Стандарт:

- оболочка: `Card`;
- заголовок: `CardTitle`, `text-base font-semibold`;
- описание: `CardDescription`, `text-sm`, `--raport-muted`;
- иконка секции: `h-5 w-5`, `--raport-primary`, `strokeWidth={2}`;
- actions справа через `actions`;
- для правого закрепления переключателей используется `pinActionsRight`;
- контент начинается с `CardContent` и `pt-0`.

Секции ССЗ:

- `Лидеры по технологии`;
- `Зона внимания`;
- `Срезы по технологии`;
- вложенные аналитические карточки `Заказы`, `Цеха`, `Мастера`, `Операции`.

Карточки списков используют единый компактный паттерн:

- верх: название слева, `% + статус` справа;
- середина: `ProgressStrip`;
- низ: метрики в одну строку;
- длинные ФИО, цеха и операции обрезаются, не переносятся.

## 6. Фильтры

Фильтры оформляются через `FilterPanel`.

Стандарт:

- карточка `Card`;
- заголовок с иконкой `Filter`;
- кнопка сброса с иконкой `RefreshCcw`;
- подписи фильтров: `text-xs`, uppercase для групп, `--raport-muted`;
- поля ввода: `Input`;
- выпадающие списки: `Select`;
- автодополнение использует локальный список с `absolute`, `z-20`, белой поверхностью, общей рамкой и тенью карточки;
- фильтры применяются автоматически;
- состав, порядок и поведение фильтров не меняются при визуальных доработках.

Целевая доля:

- подпись `Целевая доля по технологии` сверху;
- ниже в одну строку числовой `Input` слева и `range` справа;
- числовое поле компактное, рассчитано на диапазон `0-100`;
- бегунок занимает оставшуюся ширину.

## 7. Статусная полоска фильтра

Статусная полоска оформляется через `FilterStatusBar`.

Стандарт:

- карточка `Card`;
- контент: `flex min-h-12 flex-wrap items-center gap-2`;
- внутренние отступы: `!px-4 !py-3`;
- заголовок: `Активные фильтры`, `text-xs font-semibold`;
- значения фильтров: `Badge`;
- вторичный chip использует `variant="secondary"`.

Tessa должна показывать активные фильтры через этот компонент, а не отдельным кастомным блоком.

## 8. Переключатели

Переключатели оформляются через `DashboardSwitch`, внутри используется `ToggleGroup`.

Стандарт:

- контейнер: `inline-flex`, `rounded-full`, `border-[var(--raport-border)]`, `bg-slate-50`, `p-1`;
- кнопка: `min-h-7`, `rounded-full`, `px-3 py-1`, `text-xs font-semibold`;
- активное состояние: `bg-[var(--raport-action-bg-active)]`, `text-[var(--raport-primary)]`, inset-border через `--raport-action-border`;
- переключатель `ТОП/Все` закрепляется справа в шапке карточки через `SectionCard pinActionsRight`;
- переключатель статусов `Все / Цель достигнута / Ниже цели` расположен по центру под шапкой карточки.

Tessa должна использовать `DashboardSwitch` для аналогичных режимов и не создавать собственные segmented controls.

## 9. Таблицы

Базовый стандарт таблиц задает `DataTable`.

Стандарт:

- контейнер таблицы: `overflow-hidden`, общий radius `--raport-radius-control`, border `--raport-border`;
- шапка таблицы строится через `TableHead`, `TableHeaderCell`;
- строки через `TableRow`, ячейки через `TableCell`;
- пустое состояние: текст `Нет данных`, центрирование и `--raport-muted`;
- числовые колонки должны иметь `text-right` и `tabular-nums`.

В текущем ССЗ основные аналитические списки уже перешли на компактный строковый layout вместо классической таблицы. Для Tessa таблицы нужно приводить к `DataTable`, если они остаются таблицами, либо к компактному строковому паттерну ССЗ, если UX требует рейтинговых списков.

## 10. Графики

В текущей странице ССЗ отдельные графики как chart-renderer не используются. Графическое сравнение показателей реализовано через `ProgressStrip`:

- прогресс-линия `h-2`;
- серый трек `bg-slate-200`;
- цвет заполнения зависит от статуса:
  - success: `--raport-success`;
  - warning: `--raport-warning`;
  - danger: `--raport-danger`;
- маркер цели позиционируется поверх прогресса;
- целевая позиция округляется к шагу 5%;
- прогресс-линия должна быть визуально толще разделительных линий.

Для будущих графиков используется оболочка `ChartCard`, которая построена на `SectionCard`. Tessa и Print не должны вводить отдельный визуальный контейнер графика: график помещается внутрь `ChartCard` или `SectionCard`.

## 11. Использование lucide-react

Все иконки берутся из `lucide-react`.

Иконки, уже используемые в текущем ССЗ:

- `FileSpreadsheet` - бренд, файл, заказы;
- `ClipboardList` - всего ССЗ;
- `Factory` - производство, цеха, доля работ;
- `Gauge` - аналитика и срезы;
- `Users` - мастера;
- `Wrench` - операции;
- `CheckCircle2` - лидеры;
- `AlertTriangle` - зона внимания;
- `Filter` - фильтры;
- `RefreshCcw` - сброс;
- `UploadCloud` - загрузка;
- `ShieldCheck` - локальная обработка файла;
- `SearchCheck` - обработка файла.

Стандарт размеров:

- бренд: `24px`, `strokeWidth={2.3}`;
- иконка секции: `20px`, `strokeWidth={2}`;
- иконка KPI и кнопок: `16px`, `strokeWidth={2}`;
- цвет задается Tailwind-классом, обычно `text-[var(--raport-primary)]`.

Запрещены PNG и самодельные SVG-иконки для смыслов, где есть подходящая lucide-иконка.

## 12. CSS-подходы, которые нельзя менять

Запрещено менять при развитии дашбордов:

- не добавлять CSS-in-JS;
- не добавлять inline styles;
- не вводить новые dashboard-specific CSS-файлы без необходимости;
- не хардкодить цвета в компонентах, если есть `--raport-*` токен;
- не создавать новый UI-kit или сторонние компоненты вместо `shared/ui`;
- не копировать SVG вручную в React-компоненты;
- не менять глобальные CSS variables без отдельного согласования;
- не менять радиусы, тени и базовые цвета отдельно в Tessa/Print;

Допустимые CSS-источники:

- `src/shared/styles/theme.css` для общих токенов;
- Tailwind classes в React-компонентах;
- shadcn-подобные primitives из `src/shared/ui/shadcn`;

## 13. Что приводить к существующим компонентам

Новые и обновляемые элементы нужно маппить на текущие shared-компоненты:

- верх дашборда -> `DashboardHeader` с бренд-блоком `Рапорт` и слоганом;
- общая оболочка страницы -> `PageShell`;
- загрузка файла -> `FileDropZone`;
- верхние числовые показатели -> `MetricCard`;
- секции аналитики -> `SectionCard`;
- фильтры -> `FilterPanel`;
- активные фильтры -> `FilterStatusBar`;
- переключатели режимов -> `DashboardSwitch`;
- таблицы -> `DataTable`;
- графики -> `ChartCard` или `SectionCard` с текущими токенами;
- ошибки импорта или обработки -> `ErrorState`;
- пустые состояния -> `EmptyState`;
- проблемные статусы -> `Badge` / `ProblemBadge`, если нужен отдельный semantic wrapper;
- подписи с иконками -> `IconLabel`, если нужен компактный label-паттерн.

Нельзя создавать новые аналоги этих компонентов для отдельных дашбордов. Если текущего shared-компонента не хватает, сначала нужно расширить существующий компонент обратно совместимым способом и только потом использовать его в нужном дашборде.

## Итоговое правило

Развитие дашбордов должно повторять текущую визуальную систему `/ssz` из `src`: те же токены, те же shared-компоненты, те же принципы плотности, обрезки длинного текста, статусов, переключателей, карточек и прогресс-индикации.

Визуальные доработки не должны менять бизнес-логику, расчеты, фильтры, порядок виджетов, значения переключателей по умолчанию или сценарии пользователя.
