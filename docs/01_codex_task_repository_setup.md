# Codex Task 01: подготовить репозиторий для миграции по варианту «ССЗ как стиль»

## Цель

Подготовить структуру проекта `raport`.

# Технологический стандарт интерфейса

При миграции интерфейс должен использовать:

- **Tailwind CSS** — для стилей, сетки, отступов, состояний, адаптивности и цветовых токенов.
- **shadcn/ui** — для базовых UI-компонентов.
- **lucide-react** — для всех иконок.

Запрещено использовать:

- собственные SVG-иконки, если есть подходящая иконка в `lucide-react`;
- сторонние UI-kit библиотеки, кроме `shadcn/ui`;
- CSS-in-JS;
- inline styles;
- новые отдельные CSS-файлы под конкретный дашборд без необходимости;
- hardcoded-цвета внутри компонентов, если можно использовать Tailwind token или CSS variable.

Допустимо использовать CSS-файлы только для:

- общих CSS variables;
- базовых theme tokens;
- временной изоляции legacy-стилей, например `.print-dashboard`;
- технических случаев, которые сложно или нецелесообразно выразить Tailwind-классами.

Все новые или обновленные UI-компоненты должны быть React-компонентами, стилизованными через Tailwind classes и, где уместно, построенными на shadcn/ui primitives.


## Что сделать

1. Проверить текущую структуру репозитория.
2. Если нужных папок нет — создать.
3. Проверить наличие Tailwind CSS.
4. Проверить наличие shadcn/ui.
5. Проверить наличие lucide-react.
6. Если чего-то нет — предложить минимальный план подключения, но не ломать существующую сборку.
7. Не удалять существующий код.
8. Не переносить файлы без отдельного подтверждения.
9. Не менять бизнес-логику.
10. Убедиться, что `legacy/ssz` предусмотрен как визуальный источник правды.

## Проверка

После изменений выполнить:

```bash
npm run build
```

Если сборка невозможна, явно написать причину.
