# Рапорт — дизайн-система на основе дашборда ССЗ

## Назначение

ССЗ является визуальным эталоном.

Все остальные дашборды должны использовать стиль ССЗ, но сохранять свою бизнес-логику, структуру экранов, фильтры и переключатели.

# Технологический стандарт интерфейса

Интерфейс должен использовать:

- **Tailwind CSS** — для стилей, сетки, отступов, состояний, адаптивности и цветовых токенов.
- **shadcn/ui** — для базовых UI-компонентов.
- **lucide-react** — для всех иконок.

Запрещено использовать:

- собственные SVG-иконки, если есть подходящая иконка в `lucide-react`;
- сторонние UI-kit библиотеки, кроме `shadcn/ui`;
- CSS-in-JS;
- inline styles;
- новые отдельные CSS-файлы под конкретный дашборд без необходимости;
- hardcoded-цвета внутри компонентов, если можно использовать Tailwind token или CSS variable.

Допустимо использовать CSS-файлы только для:

- общих CSS variables;
- базовых theme tokens;
- технических случаев, которые сложно или нецелесообразно выразить Tailwind-классами.

Все новые или обновленные UI-компоненты должны быть React-компонентами, стилизованными через Tailwind classes и, где уместно, построенными на shadcn/ui primitives.


# Правила по иконкам

Все иконки брать только из `lucide-react`.

Не создавать собственные SVG-иконки и не копировать SVG вручную в компоненты.

Рекомендуемые иконки:

- `FileSpreadsheet` — CSV/XLS/XLSX, таблицы, файл отчета;
- `UploadCloud` — drag-and-drop загрузка;
- `ShieldCheck` — локальная обработка файла в браузере;
- `CheckCircle2` — успешное состояние;
- `AlertTriangle` — предупреждение;
- `CircleX` — ошибка;
- `SearchCheck` — определение типа отчета;
- `Gauge` — аналитика / дашборд;
- `Printer` — дашборд печати;
- `ClipboardCheck` — Tessa / исполнительская дисциплина;
- `ClipboardList` — ССЗ / задания;
- `Factory` — производственный контекст;
- `Filter` — фильтры;
- `RefreshCcw` — сброс фильтров;
- `Info` — пояснение.

Правила:

- использовать иконки сдержанно;
- иконка должна иметь смысловую функцию;
- не использовать иконки как декор;
- размер обычно 16–24 px;
- `strokeWidth={2}`;
- цвет задавать Tailwind-классами;
- для одинаковых смыслов использовать одинаковые иконки во всех дашбордах.


## Источник стиля

Действующий источник стиля:

```txt
src/shared/styles/theme.css
src/shared/ui
src/features/ssz
```

Новые экраны и виджеты должны использовать существующие токены, компоненты и паттерны текущих дашбордов. Если нужного базового компонента нет, сначала нужно проверить возможность расширить существующий компонент из `src/shared/ui`.

## Что стандартизировано

- шрифтовое оформление;
- цветовая система;
- вид загрузочного экрана;
- оформление шапки дашборда;
- оформление переключателей;
- статусная полоска фильтра;
- оформление фильтров;
- подход к использованию иконок;
- оформление KPI;
- оформление карточек;
- оформление графиков;
- оформление таблиц;
- empty/error states;
- плотность интерфейса;
- принципы отступов.

## Shared UI

Компоненты размещаются в:

```txt
src/shared/ui
```

Базовый набор:

- `PageShell`;
- `TopBar`;
- `DashboardHeader`;
- `FileDropZone`;
- `MetricCard`;
- `SectionCard`;
- `ProblemBadge`;
- `FilterPanel`;
- `FilterStatusBar`;
- `DashboardSwitch`;
- `DataTable`;
- `ChartCard`;
- `EmptyState`;
- `ErrorState`;
- `IconLabel`.

## shadcn/ui

Базовые компоненты строить на shadcn/ui:

- карточки → `Card`;
- кнопки → `Button`;
- статусы → `Badge`;
- ошибки → `Alert`;
- прогресс → `Progress`;
- разделители → `Separator`;
- таблицы → `Table`;
- фильтры → `Select`, `Input`, `Button`, `Badge`;
- переключатели → `Switch`, `ToggleGroup` или `Tabs` только при сохранении исходного поведения.

## TopBar

Визуально — в стиле ССЗ.

Функционально — только:

- название / логотип «Рапорт»;
- ссылка на главную страницу `/`.

Запрещено добавлять ссылки на дашборды.

## DashboardSwitch

Переключатели должны выглядеть как в ССЗ.

Но существующее поведение каждого переключателя сохраняется.

Запрещено менять:

- варианты переключателя;
- default state;
- данные, которые переключатель показывает;
- расположение переключателя внутри виджета.

## FilterPanel и FilterStatusBar

Фильтры должны выглядеть как в ССЗ.

Но сохранить:

- состав фильтров;
- порядок фильтров;
- значения;
- default state;
- логику применения;
- кнопку сброса;
- связи между фильтрами.

## Что нельзя делать

Запрещено:

- придумывать новую палитру вместо извлечения стиля ССЗ;
- менять layout Tessa и Print под layout ССЗ;
- менять бизнес-логику ради совпадения с ССЗ;
- удалять фильтры;
- менять поведение фильтров;
- удалять переключатели;
- менять поведение переключателей;
- делать `/print` отдельным визуальным продуктом;
- создавать собственные SVG-иконки;
- подключать другой UI-kit вместо shadcn/ui;
- писать стили через CSS-in-JS или inline styles.
