# Технологические правила интерфейса для «Рапорт»

## Стек

Интерфейс «Рапорта» строится на едином стеке:

- React;
- TypeScript;
- Tailwind CSS;
- shadcn/ui primitives;
- lucide-react;
- Vite;
- IndexedDB через нативный `window.indexedDB`.

Новые дашборды должны встраиваться в эту архитектуру, а не создавать параллельный стек.

## Tailwind CSS

Правила:

- все новые стили писать Tailwind-классами;
- цвета, радиусы, поверхности и тени брать из CSS variables в `src/shared/styles/theme.css`;
- не использовать hardcoded-цвета, если есть токен `--raport-*`;
- не плодить локальные CSS-файлы для каждого дашборда;
- локальный CSS допустим только для общего theme-layer или технического случая, который плохо выражается utility-классами;
- повторяющиеся варианты оформлять через компоненты, props, `className` и `cn()`.

## shadcn/ui

Для базовых компонентов использовать shadcn/ui primitives из `src/shared/ui/shadcn`.

Рекомендуемые primitives:

- `Card`;
- `Button`;
- `Badge`;
- `Alert`;
- `Input`;
- `Select`;
- `Table`;
- `ToggleGroup`;
- `Separator`, если добавлен в проект.

Правило: shadcn/ui — это база для доступности и структуры, но визуальный контракт задает «Рапорт» через `src/shared/ui` и `theme.css`.

## Shared UI

Перед созданием нового компонента проверить:

1. `src/shared/ui`;
2. локальные компоненты существующих дашбордов;
3. возможность расширить существующий компонент props-ами.

Базовые компоненты текущего стандарта:

- `PageShell`;
- `DashboardHeader`;
- `FileDropZone`;
- `MetricCard`;
- `SectionCard`;
- `ChartCard`;
- `FilterPanel`;
- `FilterStatusBar`;
- `DashboardSwitch`;
- `DataTable`;
- `EmptyState` / `ErrorState`;
- `IconLabel`.

Если новый дашборд требует похожий паттерн, он должен использовать этот набор.

## lucide-react

Все иконки брать только из `lucide-react`.

Запрещено:

- создавать собственные SVG-иконки;
- копировать SVG вручную в компоненты;
- использовать PNG как интерфейсную иконку;
- смешивать несколько библиотек иконок.

Рекомендации:

- размер 16–24 px;
- `strokeWidth={2}` или близко к нему;
- одинаковый смысл — одинаковая иконка во всех дашбордах;
- иконка должна помогать понять действие или смысл блока, а не быть декором.

## Архитектура дашборда

Для нового дашборда использовать слои:

```txt
src/features/<dashboard>/
  import/        // чтение и парсинг файла
  logic/         // доменные расчеты, фильтры, агрегации
  components/    // React UI текущего дашборда
  types.ts       // типы домена
```

Правила:

- не хранить бизнес-расчеты в JSX;
- не смешивать парсинг файла и UI;
- фильтрацию держать в доменном слое;
- тяжелые агрегации мемоизировать в компонентах через `useMemo`;
- крупные компоненты дробить до понятных локальных компонентов;
- повторяющиеся UI-паттерны выносить в `src/shared/ui`.

## Загрузка и определение отчетов

Главная страница `#/` — единая точка загрузки.

Правила:

- тип отчета определяется по содержимому, не по имени файла;
- определение должно быть быстрым и использовать минимально достаточную структуру;
- дашборды не должны открывать локальный файл сами;
- после загрузки данные передаются в нужный маршрут;
- при отсутствии данных на странице дашборда пользователь возвращается на главную с понятным статусом.

## Локальная история

История хранится в IndexedDB:

- база: `raport_history`;
- object store: `snapshots`;
- API: `src/shared/lib/historyDB.ts`;
- сборка данных: `src/shared/lib/snapshotBuilder.ts`.

Ограничения:

- сохранять только агрегированные числовые KPI;
- не сохранять сырые строки отчетов;
- не сохранять ФИО, пользователей, документы, темы, названия заявок;
- не добавлять сторонние библиотеки вроде `dexie` или `idb`.

Правила трендов:

- шаг тренда — месяц;
- месяц используется в тренде только при покрытии не меньше 50%;
- snapshot с большим или равным покрытием перезаписывает старый;
- snapshot с меньшим покрытием не затирает старый;
- Print snapshots считаются без печати в PDF.

## Роутинг и публикация

Используется hash-routing.

Правила:

- маршруты: `#/ssz`, `#/tessa`, `#/print`, `#/support`;
- production-сборка должна работать на любом домене и в любой папке;
- страницы дашбордов должны грузиться лениво на уровне маршрутов через `React.lazy` / `Suspense`;
- главная страница `#/` должна оставаться легким стартовым экраном и не импортировать все дашборды через общий barrel;
- не использовать абсолютные пути к ассетам;
- не переходить на BrowserRouter без отдельного решения по серверному fallback.

## Запреты

Запрещено:

- добавлять Material UI, Ant Design, Chakra UI или другой UI-kit;
- создавать собственный набор SVG-иконок;
- использовать CSS-in-JS;
- использовать inline styles;
- менять бизнес-логику ради визуального компонента;
- менять поведение фильтров ради нового UI;
- делать новый дашборд отдельным визуальным продуктом;
- сохранять персональные или сырые данные в IndexedDB.

## Проверка

Перед завершением задачи запускать:

```bash
npm run check
```

Если задача промежуточная и сборка пока не нужна, минимум:

```bash
npm run typecheck
```
