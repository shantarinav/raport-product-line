# Visual Contract Рапорта

Этот документ фиксирует визуальный контракт продуктовой линейки «Рапорт». Он нужен, чтобы новые страницы, виджеты и локальные функции выглядели как часть одного продукта, а не как набор точечных решений.

Живой эталон компонентов находится на внутренней странице `#/ui-contract`.

## Главный принцип

Визуальные решения сначала сверяются с существующими shared-компонентами, затем с `#/ui-contract`, и только после этого допускается локальная стилизация.

Запрещено:

- создавать новый стиль кнопок, пинов, карточек или шапок без причины;
- копировать Tailwind-классы из случайного места вместо переиспользования shared UI;
- использовать синий цвет для нейтральной информации, если элемент не является действием, активным фильтром или основным акцентом;
- делать декоративные иконки похожими на кнопки;
- менять визуальный смысл статусов между страницами.

## Базовые компоненты

Использовать компоненты из `src/shared/ui/`:

- `PageShell` — внешний контейнер страницы;
- `DashboardHeader` — шапка главной, дашборда, журнала и справки;
- `SectionCard` / `ChartCard` — секции и виджеты;
- `MetricCard` — KPI-карточки;
- `FilterStatusBar` — активные фильтры и компактные переключатели;
- `DashboardSwitch` — переключатели режимов;
- `QuickFocusGroup` — быстрые фокусы и компактные группы фильтров;
- `DataTable` — таблицы;
- `FileDropZone` — загрузка файла;
- `HeaderIconButton` — одиночные icon-only действия в шапках;
- `Button` из `src/shared/ui/shadcn/button` — все кнопки;
- `Badge` из `src/shared/ui/shadcn/badge` — все пины и статусы.

Если элемент повторяется минимум в двух местах, он должен быть вынесен в `src/shared/ui/`.

## Цветовая семантика

- Синий — действие, активное состояние, ссылка, текущий акцент.
- Зеленый — норма, готово, положительная динамика.
- Янтарный — контроль, внимание, отклонение без критичности.
- Красный — критично, ошибка, высокий риск.
- Серый — справочная информация, вторичные данные, нейтральные пины.

Информационные пины по умолчанию должны быть нейтральными. Синие пины использовать только для активных фильтров, ссылочных акцентов или выбранного состояния.

## Кнопки

Основные правила:

- действие с текстом — `Button`;
- одиночное действие в шапке — `HeaderIconButton`;
- основное действие внутри формы — иконка + текст;
- вторичные действия — `outline` или компактные icon-only;
- декоративные иконки не должны иметь рамку и фон кнопки.

Кнопка должна выглядеть как кнопка. Пин, подпись или декоративная иконка не должны выглядеть как кнопка.

## Пины и статусы

Пины делятся на типы:

- `default` / `secondary` — нейтральные справочные признаки;
- `accent` — активный фильтр или выбранный режим;
- `success` — завершено, подтверждено, норма;
- `warning` — контроль, требуется внимание;
- `danger` — ошибка, критично, просрочено.

Не использовать пины как замену кнопкам. Если элемент кликабельный, он должен иметь понятное состояние наведения, фокус и `aria-label` при необходимости.

## Типографика

- Заголовок страницы: крупный, уверенный, через `DashboardHeader`.
- Заголовок секции: `SectionCard` / `CardTitle`.
- Подписи и пояснения: `text-raport-muted`, без избыточного веса.
- Табличные значения: без декоративного жирного, если это не ключевой показатель.
- Не дублировать одну и ту же мысль в заголовке, подписи и пине.

## Карточки и секции

Карточки должны иметь:

- общий радиус `rounded-card` или `rounded-control`;
- границу `border-raport-border`;
- фон `bg-raport-surface` или `bg-raport-surface-soft`;
- тень только там, где она уже является частью shared-компонента.

Не создавать карточки с новым радиусом, новым цветом рамки или отдельной тенью без обновления токенов.

## Шапки страниц

Все пользовательские страницы должны использовать `DashboardHeader`.

Шапка должна содержать:

- понятное название;
- короткий слоган или подзаголовок, если нужен;
- одну строку описания управленческого смысла;
- справа — только действия страницы и переключатель темы.

Не превращать шапку в меню.

## Иконки

Все иконки — только из `lucide-react`.

Правила:

- одна и та же иконка для одного смысла во всех разделах;
- декоративная иконка: без рамки и без фона кнопки;
- action icon: рамка, фон действия, hover-state;
- не использовать похожие иконки рядом, если пользователь не понимает различие действий.

## Темы

Светлая тема — основной деловой серый стиль Рапорта.

Темная тема:

- не должна быть неоновой;
- сохраняет ту же цветовую семантику;
- не должна ухудшать читаемость графиков, таблиц, пинов и фильтров.

Цвета задаются через CSS variables в `src/shared/styles/theme.css` и Tailwind tokens из `tailwind.config.ts`.

## Анимации

Анимации допустимы только если помогают пользователю:

- мягкое дыхание drag-and-drop зоны на главной;
- аккуратные hover/focus состояния;
- загрузка или ожидание обработки.

Запрещено:

- декоративная анимация без пользы;
- движение текста или контента при декоративной анимации;
- анимации, мешающие чтению KPI и таблиц.

## Проверка перед завершением UI-задачи

Перед завершением визуальной задачи проверить:

- светлую тему;
- темную тему;
- `#/`;
- измененную страницу;
- `#/ui-contract`, если менялись shared-компоненты;
- `npm run typecheck` минимум;
- `npm run check` перед merge/release.
