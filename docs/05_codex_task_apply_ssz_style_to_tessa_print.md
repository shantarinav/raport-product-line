# Codex Task 05: применить стиль ССЗ к Tessa и Print без изменения логики

## Цель

Применить визуальную систему, извлеченную из ССЗ, к дашбордам Tessa и Print.

## Важно

Это визуальная миграция. Не менять бизнес-логику, layout, фильтры, переключатели и поведение виджетов.

# Технологический стандарт интерфейса

При миграции интерфейс должен использовать:

- **Tailwind CSS** — для стилей, сетки, отступов, состояний, адаптивности и цветовых токенов.
- **shadcn/ui** — для базовых UI-компонентов.
- **lucide-react** — для всех иконок.

Запрещено использовать:

- собственные SVG-иконки, если есть подходящая иконка в `lucide-react`;
- сторонние UI-kit библиотеки, кроме `shadcn/ui`;
- CSS-in-JS;
- inline styles;
- новые отдельные CSS-файлы под конкретный дашборд без необходимости;
- hardcoded-цвета внутри компонентов, если можно использовать Tailwind token или CSS variable.

Допустимо использовать CSS-файлы только для:

- общих CSS variables;
- базовых theme tokens;
- временной изоляции legacy-стилей, например `.print-dashboard`;
- технических случаев, которые сложно или нецелесообразно выразить Tailwind-классами.

Все новые или обновленные UI-компоненты должны быть React-компонентами, стилизованными через Tailwind classes и, где уместно, построенными на shadcn/ui primitives.


# Правила по иконкам

Все иконки брать только из `lucide-react`.

Не создавать собственные SVG-иконки и не копировать SVG вручную в компоненты.

Рекомендуемые иконки:

- `FileSpreadsheet` — CSV/XLS/XLSX, таблицы, файл отчета;
- `UploadCloud` — drag-and-drop загрузка;
- `ShieldCheck` — локальная обработка файла в браузере;
- `CheckCircle2` — успешное состояние;
- `AlertTriangle` — предупреждение;
- `CircleX` — ошибка;
- `SearchCheck` — определение типа отчета;
- `Gauge` — аналитика / дашборд;
- `Printer` — дашборд печати;
- `ClipboardCheck` — Tessa / исполнительская дисциплина;
- `ClipboardList` — ССЗ / задания;
- `Factory` — производственный контекст;
- `Filter` — фильтры;
- `RefreshCcw` — сброс фильтров;
- `Info` — пояснение.

Правила:

- использовать иконки сдержанно;
- иконка должна иметь смысловую функцию;
- не использовать иконки как декор;
- размер обычно 16–24 px;
- `strokeWidth={2}`;
- цвет задавать Tailwind-классами;
- для одинаковых смыслов использовать одинаковые иконки во всех дашбордах.


## Что применить из ССЗ

К Tessa и Print применить:

- шрифтовое оформление;
- цветовое оформление;
- оформление шапки дашборда;
- оформление загрузочного экрана, если на странице есть загрузка файла;
- оформление переключателей;
- оформление статусной полоски фильтра;
- оформление фильтров;
- подход к иконкам через lucide-react;
- оформление KPI;
- оформление карточек через shadcn/ui `Card`;
- оформление графиков;
- оформление таблиц через shadcn/ui `Table` или совместимый общий `DataTable`;
- empty/error states через shadcn/ui `Alert`, если уместно.

## Что сохранить

Сохранить:

- расчеты;
- агрегации;
- структуру данных;
- расположение виджетов;
- порядок виджетов;
- состав виджетов;
- поведение виджетов;
- фильтры;
- поведение фильтров;
- переключатели;
- значения переключателей по умолчанию;
- вкладки;
- таблицы;
- сортировки;
- графики;
- сценарии работы пользователя.

## Правила для `/print`

Старый CSS изолировать через:

```css
.print-dashboard {
  /* legacy scope */
}
```

Если старые стили мешают, сначала локализовать их, а не удалять.

## Проверка

После изменений выполнить:

```bash
npm run build
```

Проверить вручную:

- Tessa открывается;
- Print открывается;
- данные загружаются;
- KPI совпадают;
- фильтры работают как раньше;
- переключатели работают как раньше;
- таблицы сохранили данные и сортировки;
- графики сохранили данные;
- визуальный стиль соответствует ССЗ;
- стили реализованы через Tailwind;
- базовые компоненты используют shadcn/ui;
- иконки используют lucide-react.
