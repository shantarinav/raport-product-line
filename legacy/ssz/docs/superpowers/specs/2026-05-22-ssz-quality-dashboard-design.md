# Дашборд качества ССЗ: дизайн первой версии

## Контекст

В проекте есть пример XLS-файла `Статистика по качеству выдаваемых ССЗ апрель накопительным итогом 2026.xls`. В нём один лист `TDSheet` с иерархическим отчётом:

- параметры периода: начало `01.04.2026`, конец `01.05.2026`;
- уровни группировки: подразделение, мастер смены, сменно-суточное задание;
- строки операций: продукция, комплект, полуфабрикат, операция, исполнитель;
- числовые показатели: время выполнения по технологии и время выполнения без технологии.

По предварительному анализу примера файл содержит около 23 971 строки, 865 ССЗ и примерно 22 349 строк операций. Статусы ССЗ в примере: `Завершен`, `Утвержден`, `В подготовке`.

## Цель

Сделать первую версию дашборда для анализа качества выполненных сменно-суточных заданий по XLS-файлам такого формата. Главный показатель качества: доля времени, выполненного без технологии. Чем выше доля, тем хуже качество оформления или планирования ССЗ.

Дашборд должен быть универсальным отчётом для разных пользователей: руководителя, мастера, аналитика и специалиста по качеству. Первый экран должен давать управленческий обзор, а затем позволять провалиться до подразделения, мастера, ССЗ, операции и исполнителя.

## Выбранный Подход

Первая версия будет лёгким браузерным приложением без серверной части и базы данных.

Пользователь открывает приложение, загружает один или несколько XLS-файлов, данные разбираются прямо в браузере и хранятся в памяти текущей вкладки. Если загружено несколько файлов, приложение определяет периоды из строк `Начало периода` и `Конец периода` и позволяет сравнивать выбранный период с другим загруженным периодом.

В первой версии не предполагаются постоянная история загрузок, настоящие учётные записи, серверная загрузка файлов или разграничение доступа к данным. Роли могут быть отражены в терминологии интерфейса позже, но не являются системой прав в рамках этой версии.

## Пользовательский Сценарий

До загрузки данных пользователь видит пустое состояние с кнопкой загрузки XLS и кратким пояснением, какой отчёт ожидается.

После загрузки файла приложение:

1. проверяет, похож ли файл на ожидаемый отчёт;
2. извлекает период;
3. разбирает иерархию `подразделение -> мастер -> ССЗ -> операция`;
4. считает агрегаты качества;
5. показывает краткий отчёт импорта: период, количество ССЗ, количество строк операций, найденные статусы и предупреждения.

Если загружено несколько файлов, пользователь выбирает основной период и период сравнения. Сравнение работает только внутри текущей сессии браузера.

## Экраны

### Обзор Качества

Первый экран строится как обзор руководителя. Он должен быстро отвечать на вопросы:

- где самая высокая доля работ без технологии;
- как показатель изменился к выбранному периоду сравнения;
- какие подразделения, мастера, операции и ССЗ дают основной вклад в проблему;
- сколько ССЗ находится в каждом статусе.

Верхняя зона экрана:

- кнопка загрузки XLS;
- выбранный период;
- период сравнения, если загружено больше одного файла;
- фильтры по подразделению, мастеру, статусу и операции.

KPI-карточки:

- всего ССЗ;
- доля времени без технологии;
- время по технологии;
- время без технологии;
- изменение доли без технологии к периоду сравнения;
- количество проблемных ССЗ.

Основные виджеты:

- рейтинг подразделений по доле времени без технологии;
- сравнение периодов;
- распределение статусов ССЗ;
- топ операций по вкладу во время без технологии;
- топ мастеров по доле или объёму времени без технологии.

## Расчёты

Главный KPI:

```text
доля без технологии = время без технологии / (время по технологии + время без технологии)
```

Если обе части времени равны нулю или отсутствуют, доля считается неопределённой и не участвует в процентных рейтингах.

Агрегации считаются одинаково на уровнях:

- весь период;
- подразделение;
- мастер;
- ССЗ;
- операция;
- исполнитель.

Для каждого уровня рассчитываются:

- время по технологии;
- время без технологии;
- доля без технологии;
- количество ССЗ или строк операций;
- изменение к выбранному периоду сравнения.

Проблемное ССЗ в первой версии определяется как ССЗ с ненулевым временем без технологии. Порог для выделения высокой доли можно сделать настраиваемым в интерфейсе позже; в первой версии достаточно сортировки и визуального выделения верхних значений.

## Разбор XLS

Файл читается как иерархический отчёт, а не как плоская таблица.

Правила разбора:

- период берётся из верхних строк `Начало периода` и `Конец периода`;
- строка ССЗ определяется по шаблону `Сменно-суточное задание <номер> от <дата>`;
- статус ССЗ берётся из колонки статуса на строке ССЗ;
- подразделение и мастер задают текущий контекст для следующих строк;
- строки операций содержат продукцию, комплект, полуфабрикат, операцию, исполнителя и время;
- время по технологии и без технологии агрегируется на всех уровнях.

Парсер должен быть устойчивым к пустым исполнителям и частично пустым строкам операций. Такие строки импортируются, если по ним можно определить операцию и время.

## Ошибки И Предупреждения

Если файл не похож на ожидаемый отчёт, приложение показывает понятное сообщение и не строит графики.

Если часть строк неполная, приложение импортирует пригодные строки и показывает предупреждение с количеством пропущенных или неполных строк.

Если период не удалось определить, приложение разрешает анализ, но помечает период как `Не определён`.

Если несколько загруженных файлов имеют одинаковый период, приложение предлагает заменить ранее загруженный период или оставить оба варианта с суффиксом загрузки.

## Технические Границы Первой Версии

Входит в первую версию:

- браузерное приложение;
- загрузка одного или нескольких XLS-файлов;
- разбор данных в браузере;
- хранение данных в памяти текущей вкладки;
- обзорный дашборд;
- сравнение загруженных периодов в рамках текущей сессии;
- фильтры и обзорные рейтинги по подразделениям, мастерам, статусам и операциям;
- предупреждения об ошибках импорта.

Не входит в первую версию:

- серверная часть;
- база данных;
- постоянная история после перезагрузки страницы;
- настоящая авторизация;
- разграничение видимости данных по пользователям;
- экспорт данных в корпоративную БД;
- ручное редактирование импортированных строк;
- поддержка произвольных Excel-форматов, не похожих на текущий отчёт.

## Интерфейсные Принципы

Интерфейс должен выглядеть как рабочий BI-экран, а не как промо-страница. Основной упор: плотная, читаемая компоновка, быстрые фильтры, KPI и рейтинги.

Первый экран должен использовать структуру `обзор руководителя`: KPI сверху, затем рейтинги и сравнение. Карточки применяются только для KPI и повторяемых элементов. Основная рабочая область должна быть компактной и пригодной для регулярного анализа.

## Проверка

Минимальный набор проверок:

- пример XLS из проекта импортируется без критических ошибок;
- период определяется из верхних строк;
- количество ССЗ и строк операций близко к ожидаемым значениям из предварительного анализа;
- доля без технологии корректно считается на общем уровне и на уровне ССЗ;
- фильтры меняют KPI и рейтинги согласованно;
- два загруженных файла можно сравнить по выбранным периодам;
- пустой файл даёт понятную ошибку;
- файл без периода импортируется с пометкой `Не определён`;
- строки с пустым исполнителем не ломают импорт.
