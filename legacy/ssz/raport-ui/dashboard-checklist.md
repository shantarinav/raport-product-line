# Чек-лист приемки дашборда «Рапорт»

## Осмысленная компоновка

- [ ] Перед изменением кода выполнен brainstorming или краткий UX-анализ.
- [ ] Определен главный пользователь дашборда.
- [ ] Определен главный управленческий вопрос дашборда.
- [ ] Выбранная компоновка соответствует задаче дашборда, а не применена механически.
- [ ] Если есть отступления от стандартного шаблона, они объяснены пользой для пользователя.
- [ ] Главная информация видна на первом экране.
- [ ] Второстепенная информация не мешает восприятию главного.

## Бренд

- [ ] В заголовке используется формат «Рапорт: [тема]».
- [ ] На странице есть слоган «Excel докладывает главное».
- [ ] Есть краткое описание дашборда.
- [ ] Интерфейс выглядит как быстрый одностраничный дашборд из Excel.
- [ ] Интерфейс не перегружен советской или ретро-стилистикой.

## Работа с файлом

- [ ] До загрузки файла есть крупная зона загрузки или понятное пустое состояние.
- [ ] Есть кнопка «Выбрать Excel».
- [ ] После загрузки файла видно имя файла.
- [ ] После загрузки файла видно количество строк или статус обработки.
- [ ] После загрузки файла есть кнопка «Заменить файл».
- [ ] Файл можно заменить без перезагрузки страницы.
- [ ] При замене файла дашборд перестраивается.

## Фильтры

- [ ] Размещение фильтров соответствует сценарию пользователя.
- [ ] Если используется боковая панель, она называется «Фильтры» или «Фильтры рапорта».
- [ ] Есть строка «Активные фильтры» или другой понятный способ увидеть примененные фильтры.
- [ ] Есть кнопка «Сбросить фильтры».
- [ ] Активные фильтры отображаются плашками, включая начальное состояние.
- [ ] Если выбран один фильтр, остальные связанные списки показывают только релевантные значения.
- [ ] Фильтры применяются ко всем KPI, рейтингам и срезам, где это логически ожидается.
- [ ] Если фильтры применяются автоматически, нет лишней кнопки «Применить».
- [ ] Если есть фильтр по дате, после загрузки файла он заполняется периодом из файла, если период можно определить.

## KPI

- [ ] KPI оформлены карточками или другим читаемым единым блоком.
- [ ] В каждом KPI есть название показателя.
- [ ] Значение KPI отображается заметно.
- [ ] Цвета KPI используются по смыслу, а не декоративно.
- [ ] Главный KPI не смешан со вспомогательными метриками.
- [ ] Если есть целевое значение, показаны цель и отклонение от цели.
- [ ] Отклонение подписано в понятных единицах, например `п.п.` для процентных пунктов.

## Рейтинги и срезы

- [ ] Заголовки срезов короткие и не дублируют название метрики, если метрика уже объяснена в заголовке раздела.
- [ ] Подзаголовки объясняют, что именно ранжируется.
- [ ] Позитивный лидерборд имеет понятное название, например «Лидеры по технологии».
- [ ] Проблемный лидерборд имеет нейтральное управленческое название, например «Зона внимания».
- [ ] Сортировка лидербордов соответствует управленческому эффекту, а не только красивому проценту.
- [ ] Для проблемных рейтингов сначала учитывается объем проблемы, затем количество операций, затем процент.
- [ ] Для позитивных рейтингов сначала учитывается объем полезной работы, затем операции, затем процент.
- [ ] Малые выборки не искажают рейтинг.
- [ ] В строках рейтингов показаны вспомогательные метрики масштаба: нормо-часы и операции.
- [ ] Под бегунками не дублируется процент, если он уже показан крупно.
- [ ] Под бегунками показан масштаб: `н-ч всего`, `н-ч · опер. по тех.` или аналогичная полезная подпись.
- [ ] Локальная доля объекта и вклад объекта в общую проблему не перепутаны.
- [ ] Если показывается «доля без технологии», это локальная доля внутри объекта.
- [ ] Если показывается «вклад в проблему», он так и называется.

## Графики

- [ ] Графики читаемые.
- [ ] Типы графиков выбраны под управленческий вопрос.
- [ ] Цвета графиков соответствуют палитре «Рапорта».
- [ ] Красный используется только для проблем.
- [ ] Желтый используется только для рисков.
- [ ] Зеленый используется только для нормы.

## Таблицы

- [ ] Таблицы аккуратно оформлены.
- [ ] Таблица находится там, где она полезнее всего для сценария пользователя.
- [ ] Проблемные строки выделяются умеренно.
- [ ] Нет визуальной перегрузки.

## Выводы

- [ ] Если есть блок «Главное в рапорте» или «Что докладывает Excel», он строится по данным.
- [ ] Выводы помогают понять, где проблема и на что обратить внимание.
- [ ] Если выводы невозможно построить корректно, блок не добавлен формально ради шаблона.

## Технические ограничения

- [ ] Существующая логика обработки Excel не сломана.
- [ ] Бизнес-смысл показателей сохранен.
- [ ] Данные не сохраняются на сервере.
- [ ] Новые CSS-классы используют префикс `raport-`.
- [ ] Production-сборка проходит без ошибок.
- [ ] Автотесты проходят или явно указано, почему их нельзя запустить.
- [ ] В публикационный архив не попадают неиспользуемые тяжелые ассеты.
- [ ] PNG-иконки и логотипы сжаты до разумного размера.
- [ ] Пути к `assets` подходят для публикации в корне сайта или подпапке.
- [ ] Архив для хостинга содержит `index.html` и `assets/` сразу в корне архива.
