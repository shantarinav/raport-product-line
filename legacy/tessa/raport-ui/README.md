# raport-ui

Комплект файлов для приведения существующих Excel-дашбордов к единому бренду **«Рапорт»**.

## Бренд

**Рапорт — Excel докладывает главное.**

«Рапорт» — линейка быстрых одностраничных дашбордов, которые превращают Excel-файлы в понятную управленческую картину: KPI, графики, проблемные зоны и выводы.

## Важная идея

Брендбук «Рапорт» — это не жесткая сетка, а система визуальных и UX-принципов.

Codex должен не механически натягивать стиль, а сначала осмыслить:

- кто пользователь дашборда;
- какой главный вопрос он решает;
- какая информация должна быть первой;
- какая компоновка лучше помогает понять данные.

При этом не нужно перегружать интерфейс советской стилистикой. Характер бренда уже задают название «Рапорт» и слоган «Excel докладывает главное». Визуально продукт должен оставаться современным, чистым и деловым.

## Практические правила после проекта ССЗ

Эти правила добавлены по итогам реальной переделки дашборда «Рапорт: качество оформления ССЗ» и должны использоваться в следующих проектах.

1. **Сначала бизнес-смысл, потом визуал.** Перед редизайном нужно зафиксировать главный управленческий вопрос, главную метрику, вспомогательные метрики, фильтры и правила сортировки. Визуальные решения не должны менять бизнес-логику расчетов.
2. **Один главный показатель.** Не делать вспомогательные метрики равными главной. Операции, часы, количество строк и объем нужны для масштаба, сортировки и доверия к рейтингу.
3. **Короткие заголовки виджетов.** Если раздел уже объясняет метрику, карточки можно называть коротко: «Заказы», «Цеха», «Мастера», «Операции». Повторять в каждом заголовке «доля работ по технологии» не нужно.
4. **Подзаголовок объясняет роль блока.** Заголовок должен быть коротким, а подзаголовок — объяснять, что именно ранжируется и почему.
5. **Лидерборды должны быть управленческими.** Для положительного блока использовать названия вроде «Лидеры по технологии». Для проблемного блока — «Зона внимания», если важно не обвинять людей, а показать управленческий фокус.
6. **Рейтинги сортировать по эффекту.** Если задача — найти управленческий эффект, сортировать не только по проценту, а по объему: нормо-часы, операции, затем процент.
7. **Не смешивать локальную долю и вклад в проблему.** «Доля без технологии» внутри объекта — это локальная доля объекта. «Вклад в проблему» — это доля объекта в общем объеме проблемы. Нельзя подписывать одно другим.
8. **Под шкалами показывать только полезный масштаб.** Например: «н-ч всего» и «н-ч · опер. по тех.». Не дублировать процент, если он уже крупно показан рядом со шкалой.
9. **Фильтры должны быть взаимосвязанными.** Если выбран цех, список мастеров и заказов должен оставаться релевантным. Если выбран мастер, цех и заказы тоже должны подстраиваться.
10. **Публикационный пакет должен быть легким.** Перед архивом для хостинга нужно удалить неиспользуемые ассеты, сжать PNG-иконки и проверить, что пути к `assets` относительные.

## Как использовать в Codex

1. Добавьте папку `raport-ui` в проект.
2. Дайте Codex задачу:

```text
Переделай текущий дашборд по бренду «Рапорт», но сначала используй skill brainstorming.

Используй:
- raport-ui/brandbook.md
- raport-ui/theme.css
- raport-ui/refactor-prompt.md
- raport-ui/dashboard-checklist.md
- raport-ui/brainstorming-before-refactor.md
- raport-ui/icons-guide.md

После brainstorming предложи короткий план переделки, а потом приведи дашборд к бренду «Рапорт».

Обязательные элементы:
- название в формате «Рапорт: [тема]»;
- слоган «Excel докладывает главное»;
- светлый деловой стиль;
- понятная загрузка Excel;
- возможность заменить файл в процессе работы;
- цвета только по смыслу.
```
