# План миграции №2: ССЗ как визуальный эталон линейки «Рапорт»

## Цель

Собрать разрозненные дашборды в единую продуктовую линейку «Рапорт», используя текущий дашборд ССЗ как визуальный эталон.

Нужно перенести стилистику ССЗ на:

- лендинг `/`;
- дашборд `/tessa`;
- дашборд `/print`.

При этом сохранить бизнес-логику, расположение, фильтры, переключатели и поведение всех существующих дашбордов.

# Технологический стандарт интерфейса

При миграции интерфейс должен использовать:

- **Tailwind CSS** — для стилей, сетки, отступов, состояний, адаптивности и цветовых токенов.
- **shadcn/ui** — для базовых UI-компонентов.
- **lucide-react** — для всех иконок.

Запрещено использовать:

- собственные SVG-иконки, если есть подходящая иконка в `lucide-react`;
- сторонние UI-kit библиотеки, кроме `shadcn/ui`;
- CSS-in-JS;
- inline styles;
- новые отдельные CSS-файлы под конкретный дашборд без необходимости;
- hardcoded-цвета внутри компонентов, если можно использовать Tailwind token или CSS variable.

Допустимо использовать CSS-файлы только для:

- общих CSS variables;
- базовых theme tokens;
- временной изоляции legacy-стилей, например `.print-dashboard`;
- технических случаев, которые сложно или нецелесообразно выразить Tailwind-классами.

Все новые или обновленные UI-компоненты должны быть React-компонентами, стилизованными через Tailwind classes и, где уместно, построенными на shadcn/ui primitives.


## Этапы

### Этап 1. Подготовка

Положить старые проекты в `legacy/`.

Проверить наличие или подключить:

- Tailwind CSS;
- shadcn/ui;
- lucide-react.

### Этап 2. Аудит визуального стиля ССЗ

Codex должен проанализировать `legacy/ssz` и создать:

```txt
docs/ssz-visual-style-audit.md
```

Отчет должен описывать:

- цветовую систему;
- типографику;
- Tailwind-паттерны;
- shadcn/ui компоненты или аналоги, которые можно заменить на shadcn/ui;
- используемые иконки и соответствующие им lucide-react иконки;
- шапку дашборда;
- загрузочный экран;
- переключатели;
- статусную полоску фильтра;
- блок фильтров;
- карточки;
- графики;
- таблицы;
- отступы;
- состояния ошибок и пустых данных.

На этом этапе ничего не менять.

### Этап 3. Аудит Tessa и Print

Codex должен проанализировать `legacy/tessa` и `legacy/print`.

Зафиксировать:

- расчеты;
- KPI;
- графики;
- таблицы;
- фильтры;
- переключатели;
- расположение виджетов;
- порядок виджетов;
- CSS;
- риски миграции;
- где можно заменить базовые элементы на shadcn/ui без изменения поведения;
- какие иконки заменить на lucide-react.

На этом этапе ничего не менять.

### Этап 4. Shared UI на основе ССЗ

Создать `shared/ui` и `theme.css` на основе ССЗ.

Компоненты должны использовать Tailwind. Базовые UI primitives брать из shadcn/ui. Иконки брать из lucide-react.

### Этап 5. Лендинг в стиле ССЗ

Применить стиль ССЗ к лендингу и сохранить текущую логику загрузки файла.

### Этап 6. Tessa в стиле ССЗ

Применить стиль ССЗ к `/tessa`, не меняя бизнес-логику, расположение, фильтры и переключатели.

### Этап 7. Print в стиле ССЗ

Применить стиль ССЗ к `/print`, не меняя бизнес-логику, расположение, фильтры и переключатели.

Старый CSS изолировать через `.print-dashboard`.

### Этап 8. Финальная проверка

Проверить:

- маршруты;
- локальную загрузку файла;
- фильтры;
- переключатели;
- KPI;
- таблицы;
- графики;
- соответствие стилю ССЗ;
- отсутствие самодельных иконок;
- использование Tailwind / shadcn/ui / lucide-react;
- `npm run build`.
